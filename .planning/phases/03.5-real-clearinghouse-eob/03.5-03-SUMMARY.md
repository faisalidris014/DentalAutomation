## x12-parser actual API surface (vs RESEARCH.md sketch)

RESEARCH.md §"Pattern 2" sketched `import { X12Parser } from 'x12-parser'`
with `seg.name` and `seg.elements: string[]`. The verified real API
diverges:

| What RESEARCH.md said | What `x12-parser@1.3.0` actually exports |
|----------------------|-----------------------------------------|
| `X12Parser` class | `X12parser` (lowercase 'p') |
| `seg.elements: string[]` (0-indexed array) | `seg["1"]`, `seg["2"]`, ... (1-indexed string-numeral keys) |
| Composite SVC01: split manually on `:` | Pre-split: `seg["1"]` = qualifier, `seg["1-1"]` = sub-element |
| Stream API takes Readable pipe | Same — confirmed Transform stream, async iterator works directly |

The parser source comment block at the top of `edi835-parser.ts` documents
all of these so future executors don't have to re-derive.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Delta Dental fixture BPR/CLP mismatch**

- **Found during:** Task 2 RED-phase test design
- **Issue:** `delta-dental-anonymized.835.txt` had `BPR=840.00` but four claims
  paying $180 each = $720 sum. Strict reconciliation would always fail on this
  fixture, breaking the multi-claim test.
- **Fix:** Changed `BPR=840.00` → `BPR=720.00` so the fixture is internally
  consistent (4 × $180 = $720, with no PLB).
- **Files modified:** `server/adapters/payer/clearinghouse/__fixtures__/delta-dental-anonymized.835.txt`
- **Commit:** `203a46d`

**2. [Rule 1 - Bug] Plan's BPR05 = check-number assumption is wrong for 5010 X221A1**

- **Found during:** Task 1 implementation when smoke-testing parser on `cms-sample-1`
- **Issue:** Plan's pseudocode (line 296) read `payment.checkNumber = el(seg, "5")`
  which would have populated `payment.checkNumber` with `"CCP"` (the X12 payment
  format code), not a check identifier. The downstream defensive check in the
  mapper (`if (!parsed.payment.checkNumber)`) would still pass — but the value
  would not be a usable identifier for `(clinicId, checkNumber, payerName)`
  dedup downstream.
- **Fix:** Use TRN02 (trace number) as canonical `checkNumber`. In X12 5010
  X221A1 BPR has no check-number element; TRN02 is the unique payment identifier
  matching the bank-side EFT. The parser falls back to BPR sources only if TRN02
  is absent.
- **Files modified:** `server/adapters/payer/clearinghouse/edi835-parser.ts`
- **Commit:** `a0a0a88`
