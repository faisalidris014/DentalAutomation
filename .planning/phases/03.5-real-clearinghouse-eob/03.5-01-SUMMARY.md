## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Added `passWithNoTests: true` to vitest.config.ts**
- **Found during:** Task 1 (Install Vitest and add npm scripts)
- **Issue:** Vitest 1.x defaults to exiting with code 1 when no test files are found. The plan's done criterion says `npm test` must exit 0 on an empty suite. Without `passWithNoTests: true`, the verify step fails.
- **Fix:** Added `passWithNoTests: true` to the `test` block in vitest.config.ts.
- **Files modified:** `vitest.config.ts`
- **Verification:** `npm test` exits 0 with the empty Wave 0 suite.
- **Committed in:** `2d4b0a5` (Task 1 commit)

**2. [Rule 3 - Blocking] Loosened anonymization grep gate to allow X12-mandated 9-digit envelope fields**
- **Found during:** Task 2 (Create anonymized 835 fixtures)
- **Issue:** The plan's verify command rejected ANY 9-digit run other than the two test NPIs (1234567890, 9876543210). But the 835 5010 X221A1 spec REQUIRES 9-digit values in ISA13 (interchange control number), GS06 (group control number), and ST02 (transaction set control number). These are envelope identifiers — not PHI. Strict enforcement made it impossible to write a spec-compliant 835.
- **Fix:** Updated the README.md anonymization recipe to document that X12 envelope fields (ISA13, GS06, ST02) and 9-digit NPIs are the ONLY permitted 9-digit runs. Updated the threat-model verification approach to allow these fields explicitly while still rejecting unknown 9-digit runs (which would catch SSN-shaped leaks).
- **Files modified:** `server/adapters/payer/clearinghouse/__fixtures__/README.md`
- **Verification:** All 7 fixtures parse as valid 835 5010 X221A1 envelopes; no SSN-shaped runs present outside permitted X12 fields and known NPIs.
- **Committed in:** `ec0001b` (Task 2 commit)
