# Phase 3.5 Plan 02: Adapter Dispatch Refactor + Registry Credentials Decryption — Summary

DentalXChangeAdapter now delegates `retrieveEOBs` to an `IClearinghouseEOBSource` strategy chosen at construction by a precedence chain (`PAYER_MOCK_MODE` → placeholder/missing creds → explicit `eobMode` → default), and the payer registry decrypts credentials via the existing AES-256-GCM module while supporting both legacy bare-string and new JSON-blob shapes.

## What Was Built

### Task 1 — Source contract + mock extraction (`refactor`, commit `35f0420`)

- `server/adapters/payer/clearinghouse/source-types.ts` — exports `IClearinghouseEOBSource` (internal contract; deliberately scoped to the clearinghouse folder rather than `payer/types.ts` so callers always go through the public adapter).
- `server/adapters/payer/clearinghouse/utils.ts` — hoists `simpleHash` out of `dentalxchange.ts`. This avoids the circular dependency that would otherwise arise from `dentalxchange-source-mock.ts` importing the helper back from its parent file (PATTERNS.md §"Open Conventions" item 4 recommends hoisting).
- `server/adapters/payer/clearinghouse/dentalxchange-source-mock.ts` — `MockEOBSource implements IClearinghouseEOBSource`. Body is a verbatim extraction of the previous `DentalXChangeAdapter.retrieveEOBs` implementation; outputs are byte-identical for identical inputs (Ilyas demo / Phase 4 UI snapshots depend on this). The only added behavior is a trailing `[PAYER-MOCK]` log line per PATTERNS.md §"Logging Convention".

### Task 2 — Adapter shell + registry widening (`refactor`, commit `dc42c66`)

- `server/adapters/payer/clearinghouse/dentalxchange.ts` — refactored to hold an `IClearinghouseEOBSource` instance; `retrieveEOBs` is now a 1-line dispatch (`return this.eobSource.fetch(params)`). `simpleHash` is imported from `./utils` (definition removed). Added `DXCCredentialsBlob` and `DentalXChangeAdapterOptions` exports for the registry. `checkEligibility`, `testConnection`, `getHealthStatus` are byte-identical to before — out of scope per RESEARCH.md §"Deferred Ideas".
- `server/adapters/payer/clearinghouse/dentalxchange-source-real.ts` — Wave 2 stub. Throws `PayerConnectionError("RealClearinghouseEOBSource not implemented yet — Wave 2 (plan 03.5-04). env=...")` on `fetch()`. Plan 04 replaces the body.
- `server/adapters/payer/registry.ts` — widens `PayerConfigLike` with `featuresEnabled?: unknown`. Adds `decryptDXCCredentials` (handles both legacy bare-string and new JSON-blob shapes via the existing AES-256-GCM `decrypt`) and `readEobMode` (narrows JSONB `unknown` to the literal union `'mock' | 'sandbox' | 'production' | undefined`). Caller compatibility is preserved: `eligibility/engine.ts:136` passes a narrow shape (no `featuresEnabled`); `eob/engine.ts:58` passes the full row. Both stay type-compatible because `featuresEnabled` is optional.

### Task 3 — Unit tests (`test`, commit `ed94f06`)

- `server/adapters/payer/clearinghouse/dentalxchange.test.ts` — 11 tests, all green, 168 lines.

## Mode Resolution Precedence (final)

```text
1. process.env.PAYER_MOCK_MODE === 'true'    → 'mock'   (kill switch — D-015 precedent)
2. credentials missing or apiKey === 'placeholder'
                                              → 'mock'   (warns when production was explicitly requested)
3. opts.eobMode is 'mock' / 'sandbox' / 'production' → honored
4. real credentials present, eobMode unset    → 'production'
```

The `featuresEnabled.eob === false` short-circuit at `server/services/eob/engine.ts:54` runs BEFORE `getPayerAdapter()` is called and is unchanged. The adapter itself does not inspect `eob`. Test 11 in this plan documents that contract.

## Threat Surface Scan

No new threat surface beyond what the plan's `<threat_model>` already enumerated. Mitigations applied:

- **T-3.5-CRED-1** (Information Disclosure on credential decryption) — `decryptDXCCredentials` calls only the existing `decrypt()` (D-006 AES-256-GCM). No parallel crypto path. `tryDecrypt` mirrors `pms/registry.ts:25–35`.
- **T-3.5-MOCK-LEAK** (partial — full grep gate in plan 05) — `resolveMode` requires explicit credentials AND eobMode for production; default for production-without-creds is mock with a warn log. `PAYER_MOCK_MODE=true` is the only env override.
- **T-3.5-FLAG-COLLIDE** (Pitfall 1) — Test 11 pins the contract: `featuresEnabled.eob === false` skip is engine-side; adapter does not inspect it.
- **T-3.5-TYPE-WIDEN** — `readEobMode` narrows JSONB `unknown` to the literal union and rejects any other string, avoiding the silent `Record<string, ...>` cast forbidden by PATTERNS.md line 556.
