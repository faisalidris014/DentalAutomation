### `server/adapters/payer/clearinghouse/dentalxchange-source-real.ts` (new — HTTP client + orchestrator combined per RESEARCH.md)

**Analog:** `server/adapters/pms/opendental/client.ts`

**Imports pattern** (mirror `client.ts:1–2`):
```typescript
import { PayerConnectionError } from '../types';   // analog: PMSConnectionError in OD client
```

**Module-level constants** — copy verbatim from `client.ts:4–6`:
```typescript
// SOURCE: server/adapters/pms/opendental/client.ts:4–6
const TIMEOUT_MS = 30000;
const MAX_RETRIES = 3;
const RETRY_BASE_MS = 1000;
```

**Core `request<T>` pattern with retry / backoff / abort** — copy the exact loop from `client.ts:33–90`:
```typescript
// SOURCE: server/adapters/pms/opendental/client.ts:47–89
let lastError: Error | null = null;
for (let attempt = 0; attempt < MAX_RETRIES; attempt++) {
  try {
    const controller = new AbortController();
    const timeoutId = setTimeout(() => controller.abort(), TIMEOUT_MS);
    const response = await fetch(url, {
      method,
      headers: { 'Authorization': this.authHeader, 'Content-Type': 'application/json' },
      body: body ? JSON.stringify(body) : undefined,
      signal: controller.signal,
    });
    clearTimeout(timeoutId);
    if (!response.ok) {
      const text = await response.text().catch(() => '');
      if (response.status >= 500 && attempt < MAX_RETRIES - 1) {
        lastError = new PMSConnectionError(`OpenDental API error ${response.status}: ${text}`);
        await new Promise((r) => setTimeout(r, RETRY_BASE_MS * Math.pow(2, attempt)));
        continue;
      }
      throw new PMSConnectionError(`OpenDental API error ${response.status}: ${text}`);
    }
    const data = await response.json();
    return data as T;
  } catch (err) {
    if (err instanceof PMSConnectionError) throw err;
    lastError = err instanceof Error ? err : new Error(String(err));
    if (attempt < MAX_RETRIES - 1) {
      await new Promise((r) => setTimeout(r, RETRY_BASE_MS * Math.pow(2, attempt)));
      continue;
    }
  }
}
throw lastError ?? new PMSConnectionError('Unknown error');
```
**Adapt for the new file:** swap `PMSConnectionError` → `PayerConnectionError`, swap log prefix `OpenDental` → `DentalXChange`. Do NOT skip retry-on-5xx, abort-on-timeout, or `attempt < MAX_RETRIES - 1` — these are load-bearing.

**PHI-safe error message** — RESEARCH.md Pitfall 4 forbids embedding raw EDI in errors. When wrapping `x12-parser` failures:
```typescript
// PHI-safe — never include raw EDI text in the message
throw new PayerConnectionError(`835 parse failed: segment ${segName} at offset ${offset}`);
```
This contradicts the OpenDental client's `${response.status}: ${text}` (which echoes server response) — the difference is that DXC's response body MAY contain PHI in error cases. The planner must decide whether to keep the response text or strip it; recommendation is to strip the body and log `status` + `endpoint` only.

**Anti-pattern to avoid** — OpenDental client at `client.ts:13` (`private lastRequestTime = 0`) implements rate-limit throttling per-instance. The new adapter is constructed per `getPayerAdapter` call, which is per `eob_sync` job execution, NOT per process — instance-level throttling will reset between jobs. If DXC publishes a rate limit, **store throttle state on the module** (module-level `let lastRequestTime`) or skip throttling entirely until DXC docs are obtained. Flag as an open convention.

**Pagination loop pattern** — if DXC returns ERA references in pages, copy the `getAll<T>` shape from `client.ts:104–128`:
```typescript
// SOURCE: server/adapters/pms/opendental/client.ts:104–128
const allItems: T[] = [];
let offset = 0;
while (true) {
  const items = await this.get<T[]>(endpoint, { ...params, Limit: String(this.pageLimit), Offset: String(offset) });
  if (!Array.isArray(items)) return items ? [items as T] : [];
  allItems.push(...items);
  if (items.length < this.pageLimit) break;
  offset += this.pageLimit;
}
return allItems;
```

**Multi-step fetch orchestration pattern** — for the "GET ERA list → for each ERA, GET 835 EDI" flow, copy the per-item try/catch + skip-and-log pattern from `adapter.ts:128–144`:
```typescript
// SOURCE: server/adapters/pms/opendental/adapter.ts:128–144
for (const patPlan of patPlans) {
  try {
    const insSub = await this.client.get<ODInsSub>(`/inssubs/${patPlan.InsSubNum}`);
    const insPlan = await this.client.get<ODInsPlan>(`/insplans/${insSub.PlanNum}`);
    const carrier = await this.client.get<ODCarrier>(`/carriers/${insPlan.CarrierNum}`);
    plans.push(mapInsurancePlan(patPlan, insSub, insPlan, carrier));
  } catch {
    console.error(`[OpenDental] Failed to resolve insurance plan for PatPlan ${patPlan.PatPlanNum}`);
  }
}
```
**Adapt:** loop over ERA references, try/catch around the GET-EDI + parse + map sequence, log as `[DXC]` on a per-ERA failure, continue to the next ERA. Don't fail the whole `retrieveEOBs` call because one ERA was malformed — the engine's outer try/catch (`engine.ts:121–124`) will increment `errors` and the run stays partial-success.

```typescript
// SOURCE: server/adapters/pms/registry.ts:25–35
function tryDecrypt(value: string): string {
  // If the value contains ':' it's likely encrypted (iv:tag:ciphertext format)
  if (value.includes(':')) {
    try {
      return decrypt(value);
    } catch {
      return value;
    }
  }
  return value;
}
```
Why: `payer_configs.credentials` is `text` — historically may store either encrypted (iv:tag:ciphertext per `services/encryption/credentials.ts:13–28`) or plaintext (legacy). The OpenDental registry already handles this dual-shape case; the payer registry currently does NOT decrypt at all. Phase 3.5 must add a `decryptDXCCredentials(rawConfig)` function in the same shape as `decryptOpenDentalConfig` (`pms/registry.ts:12–23`), supporting:
- Legacy: `credentials` is a single encrypted string → decrypt to `{ apiKey: <decrypted> }`
- New: `credentials` is an encrypted JSON blob → decrypt then `JSON.parse` into `{ eligibility?: {...}, payment?: {...} }`

This is RESEARCH.md Pitfall 6 — DXC may issue distinct credentials per API surface.

**Switch-statement pattern** — copy `pms/registry.ts:37–46`:

## Shared Patterns

### Authentication (encryption of credentials)

**Source:** `server/services/encryption/credentials.ts` (full file, 46 lines).
**Apply to:** any new code reading `payer_configs.credentials` or any new `DXC_*` secret.

```typescript
// SOURCE: server/services/encryption/credentials.ts:13–28
export function encrypt(plaintext: string): string {
  const key = getKey();
  const iv = randomBytes(IV_LENGTH);
  const cipher = createCipheriv(ALGORITHM, key, iv);
  let encrypted = cipher.update(plaintext, 'utf8');
  encrypted = Buffer.concat([encrypted, cipher.final()]);
  const authTag = cipher.getAuthTag();
  return [
    iv.toString('base64'),
    authTag.toString('base64'),
    encrypted.toString('base64'),
  ].join(':');
}
```
**Rule:** never re-implement AES wrapping; always import `encrypt` / `decrypt` from this module. Encrypted-string format is `iv:tag:ciphertext` (colon-separated base64). The `tryDecrypt` helper in `pms/registry.ts:25–35` is the canonical "is-it-encrypted-or-plaintext" detector — copy that exact body when adding `decryptDXCCredentials`.

### Error Handling

**Source:** `server/adapters/payer/types.ts:95–107` and `server/adapters/pms/opendental/client.ts:67–73, 78–85`.
**Apply to:** every HTTP call in `dentalxchange-source-real.ts` and every parser call in `edi835-parser.ts`.

```typescript
// SOURCE: server/adapters/payer/types.ts:102–107
export class PayerConnectionError extends Error {
  constructor(message: string) {
    super(message);
    this.name = 'PayerConnectionError';
  }
}
```
- Throw `PayerConnectionError` for HTTP 5xx after retries, EDI parse failures, and reconciliation failures (BPR ≠ sum(CLP) + net(PLB)).
- Do NOT catch `PayerConnectionError` inside the adapter and convert to mock data — let it propagate to the engine's outer try/catch (`engine.ts:121–129`), which increments `errors` and continues with the next config.
- Do NOT use `console.error(err)` and swallow — the engine logs at `[EOB]` prefix once per failure (`engine.ts:122, 127`); the adapter itself should throw, not log+return-empty.

**PHI-safe error messages (RESEARCH.md Pitfall 4):** when wrapping `x12-parser` failures, never include raw EDI in the message. Use `'835 parse failed: <segment-name> at offset <N>'` with no sample text.
